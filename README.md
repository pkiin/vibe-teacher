# vibe-teacher

바이브 코딩 프로젝트. AI 코딩 도구(Claude Code, Codex CLI, GitHub Copilot)의 로컬 채팅 기록을 읽어

- **내가 쓴 메시지만** 뽑아 보여 주고 (도구 결과·시스템 주입 메시지 제외)
- **무엇이 만들어졌는지** 정리하고 (생성/수정/삭제 파일, 실행 명령, 설치 패키지, 커밋, 기술 스택)
- **알아야 할 개념**을 골라 설명하고 (규칙 기반 사전 + AI 설명)
- **이번 세션에서 확인할 것**을 근거와 함께 정리하고, 옆의 **도움 패널**에서 설명·질문·퀴즈로 이어 보고
- 프로젝트마다 **레포 위키**(이 레포가 무엇이고 어떻게 동작하는지)를, 사용자마다 **내 지식 위키**(어떤 개념을 어디서 만났고 무엇으로 확인했는지)를 계속 갱신하고 (실험 기능, 아래 참고)
- **보안 및 취약점 점검**에서 근거가 있는 주의사항과 추가 확인 방법을 따로 살펴보고
- 오른쪽 위 **설정(톱니바퀴)**에서 글씨·화면 밀도·테마·설명 난이도를 고르고
- 근거 파일을 **코드 팝업**에서 읽고, **코드 연결 흐름도**에서 실제 파일을 따라가며 이해하고
- 이 모든 설명 문장을 **읽는 사람 수준**(비개발자 · 입문 · 주니어 · 숙련, 기본은 비개발자)에 맞춰 AI 가 쓰는

로컬 웹 앱입니다. 계정(홈 디렉터리) › 프로젝트(작업 폴더) › 세션 계층으로 정리합니다.

같은 계정에서 여러 도구가 **같은 실제 폴더**를 가리키면 하나의 프로젝트로 모읍니다. 심볼릭 링크 때문에 기록된 경로가 달라도 실제 경로를 확인해 세션을 합칩니다. 이름이 같아도 다른 폴더이거나 다른 계정이면 별개로 유지하며, 없거나 읽을 수 없는 폴더는 기록된 경로를 사용합니다. Git 원격 주소가 같아도 별도로 복제한 폴더나 worktree는 자동으로 합치지 않습니다.

업데이트 후 서버를 다시 시작하고 브라우저를 새로고침하면 통합된 목록을 볼 수 있습니다. 예전 프로젝트 링크도 대표 프로젝트로 연결됩니다. 양쪽에 저장한 세션 위키·AI 설명·질문 기록·레포 위키 갱신 이력을 함께 읽으며, 레포 위키는 가장 최근 판을 보여 줍니다. 예전 저장 파일은 보존하고 새 기록은 대표 프로젝트에 저장합니다. 통합 후 레포 위키에 새 세션 안내가 뜨면 **업데이트**를 눌러 합쳐진 세션을 반영합니다.

## 빠른 시작

Node.js 20 이상이 필요합니다 (`node --version` 으로 확인).

```bash
npm install
npm run dev        # API http://127.0.0.1:8787 + 웹 http://127.0.0.1:5173
```

배포용:

```bash
npm run build && npm start   # http://127.0.0.1:8787 에서 UI 와 API 를 함께 서빙
```

### 포트와 주소 지정

우선순위는 **CLI 인자 > 환경변수 > `.env` > 설정 파일(`server.port`/`server.host`) > 기본값** 입니다. 환경변수는 저장소 루트의 `.env` 에 적어 둘 수도 있습니다 (`cp .env.example .env`, 아래 "AI 문장과 제공자" 참고).

```bash
npm run dev -- --port 3050 --api-port 3060          # 웹 3050, API 3060 (프록시도 3060 을 따라감)
npm run dev -- --host 0.0.0.0 --api-host 0.0.0.0    # 외부에서 접속 (VIBE_TEACHER_TOKEN 필요)
npm run dev -- --home /srv/vibe-teacher             # 설정·캐시 디렉터리
npm run dev -- --help

npm start -- --port 3060 --host 127.0.0.1           # 배포용 서버 (API + UI 한 포트)
npm run dev:server -- --port 3060                   # API 만
npm run dev:web -- --port 3050                      # 웹만 (vite 옵션 그대로)
```

| 환경변수 | 뜻 | 기본값 |
|---|---|---|
| `VIBE_TEACHER_PORT` | API(Hono) 포트. 웹 개발 서버의 `/api` 프록시 대상도 이 값을 따름 | 8787 |
| `VIBE_TEACHER_HOST` | API 바인딩 주소 (loopback 이 아니면 `VIBE_TEACHER_TOKEN` 필수) | 127.0.0.1 |
| `VIBE_TEACHER_WEB_PORT` | 웹(Vite) 개발 서버 포트 | 5173 |
| `VIBE_TEACHER_WEB_HOST` | 웹 개발 서버 바인딩 주소 | 127.0.0.1 |
| `VIBE_TEACHER_API_URL` | 웹 개발 서버가 프록시할 API 주소를 통째로 지정 (원격 API 등) | `http://127.0.0.1:$VIBE_TEACHER_PORT` |
| `VIBE_TEACHER_HOME` | 설정 파일과 캐시 위치 | `~/.vibe-teacher` |
| `VIBE_TEACHER_TOKEN` | 비-loopback 바인딩 시 요구되는 Bearer 토큰 | 없음 |
| `ANTHROPIC_API_KEY` | AI 분석을 Anthropic API 로 실행할 때의 키 (없으면 로그인된 Claude Code CLI 사용) | 없음 |
| `OPENROUTER_API_KEY` | AI 를 OpenRouter 로 실행할 때의 키 (무료 모델도 필요) | 없음 |
| `OPENAI_API_KEY` | AI 를 OpenAI 로 실행할 때의 키 | 없음 |
| `VIBE_TEACHER_LLM_PROVIDER` | AI 제공자 강제 (`auto` · `claude-cli` · `anthropic-sdk` · `openrouter` · `openai` · `none`), 화면에서 고른 값보다 우선 | 설정값 (`auto`) |

지정한 포트가 이미 사용 중이면 다른 포트로 조용히 옮기지 않고 바로 실패합니다(`strictPort`).

```bash
npm run typecheck
npm test
```

### 내가 쓴 메시지를 구분하는 기준

도구마다 기록 형식에 맞춰 직접 입력한 요청을 구분합니다. Codex는 내부 검토·위임용 하위 세션을 대화 목록에서 제외하고, IDE의 열린 파일 목록·환경 정보·저장소 지침 등 자동으로 붙은 문맥을 걷어낸 요청 본문만 보여 줍니다. 실제 입력 이벤트가 없는 예전 기록은 메시지 본문을 같은 기준으로 구분합니다. 코드 블록에 직접 붙인 예시는 보존합니다.

업데이트 후 서버를 다시 시작하면 기존 세션 목록 캐시를 새 기준으로 갱신합니다. 브라우저에서 새로고침하면 수정된 목록과 메시지를 볼 수 있습니다.

## 설정 파일

`~/.vibe-teacher/config.json` (`VIBE_TEACHER_HOME` 으로 위치 변경). UI 의 소스 설정 페이지에서 편집합니다.

```json
{
  "version": 1,
  "scan": { "mode": "current", "homes": [], "homeRoots": ["/home"] },
  "sources": [{ "id": "…", "provider": "claude-code", "path": "/mnt/backup/.claude/projects", "label": "백업", "enabled": true }],
  "disabledDefaultSourceIds": [],
  "llm": { "provider": "auto", "claudeCliPath": null, "model": null, "maxBudgetUsd": 0.5, "timeoutMs": 180000, "effort": "medium", "openrouterModel": "openrouter/free", "openaiModel": "gpt-5-mini", "autoText": true },
  "server": { "host": "127.0.0.1", "port": 8787 },
  "wiki": { "briefTokenBudget": 900, "maxPrerequisiteDepth": 2, "maxPrerequisitesPerBundle": 4, "maxOptionalQuestions": 2, "suggestQuestions": true }
}
```

- `scan.mode`: `current`(현재 계정만) · `list`(`homes` 에 적은 홈 디렉터리) · `all`(`homeRoots` 아래 모든 홈 + `/etc/passwd` 의 uid ≥ 1000)
- `llm.autoText`: 사람이 읽는 문장(레포 위키, 내 지식 설명, 세션 위키 설명)을 AI 가 자동으로 쓸지. 끄면 규칙 기반 문장으로 보여 줍니다.
- `wiki`: 프로젝트 위키 설명 계획의 개발용 초기값입니다 (검증된 적정값이 아님). 첫 화면 분량(근사 토큰), 선행 개념 경로 깊이와 개수 상한, 세션당 제안할 이해 확인 문제 수, 문제 제안 여부.
- 인덱스 캐시는 `~/.vibe-teacher/cache/index/`, AI 분석 결과는 `~/.vibe-teacher/cache/enrich/`, 위키와 내 이해 정보는 `~/.vibe-teacher/wiki/` 에만 기록됩니다. 스캔 대상 홈에는 아무것도 쓰지 않습니다.

## 위키 세 단계 (실험 기능)

| 위키 | 어디서 | 무엇을 |
|---|---|---|
| **레포 위키** | 프로젝트 화면 › 레포 위키 탭 | 이 저장소가 무엇이고, 어떻게 쓰고, 어떻게 동작하는지 (프로젝트 소개 / 동작 방식 / 보안 점검) |
| **내 지식 위키** | 상단 메뉴 › 내 지식 (프로젝트·세션 화면에도 관련 부분) | 내가 만난 개념마다 어디서 왜 나왔고, 지금까지 무엇으로 확인됐는지 |
| **이번 세션에서 확인할 것** | 세션 화면 › 이번 세션 이해하기 탭 | 그 세션 대화에서 확인된 사실, 아직 확인되지 않은 것, 먼저 볼 위험 |

### 레포 위키

프로젝트 화면의 **레포 위키** 탭에서 "레포 위키 만들기"를 누르면, 저장소 폴더를 **읽기 전용으로** 살펴본 결과와 그 프로젝트의 세션 기록(최근 60개)을 합쳐 세 가지 보기로 정리합니다.

- **어떤 프로젝트인가요?**: 어떤 프로젝트인가요 · 제공하는 기능 · 설치와 실행 · 설정할 것 · 알아 둘 점 · 변경 이력
- **어떻게 동작하나요?**: 폴더 구조와 역할 · 사용하는 기술 · 시작 파일과 실행 순서 · 코드 연결과 주요 처리 · 데이터를 주고받는 주소(API) · 데이터와 외부 연동 · 테스트와 검증 · 주의할 동작
- **보안 및 취약점 점검**: 각 세션에서 찾은 보안·데이터 주의사항, 영향과 근거 상태, 확인 방법, 추가로 필요한 자료. 같은 규칙이 여러 세션에서 나와도 각 세션의 근거를 보존합니다.

**누가 무엇을 쓰나**: 사실(실행 명령, 스크립트, 설정 변수, API·라우트, 폴더, 변경 이력)은 코드가 저장소와 세션 기록에서 모으고, 그 사실 초안을 바탕으로 **AI 가 절마다 읽기 좋은 문장을 씁니다**. 명령·API·폴더 표와 코드 블록은 저장소에서 읽은 그대로 두고 AI 는 바꾸지 못합니다. 보안 및 취약점 점검 절도 확인 범위와 주의사항이 바뀌지 않도록 기록 그대로 유지합니다. AI 가 붙인 근거 중 실제로 없는 파일·세션은 빼고 경고로 남깁니다. AI 가 쓰는 동안(보통 1~3분) "AI가 문장을 쓰는 중"이 보이고, 취소할 수 있습니다. 문장은 **내 읽는 사람 수준**(아래)에 맞춰 쓰며, 처음 만들 때 수준을 아직 고르지 않았으면 만들기 버튼 위에서 먼저 고르게 합니다. 수준마다 문장을 따로 저장하므로, 같은 판을 다른 수준의 사람이 열면 그 수준으로 새로 쓰고 이미 쓴 수준은 다시 부르지 않습니다. 위키 위쪽에 누가 썼는지(제공자·모델)가 표시되며, AI 를 쓸 수 없을 때(아래 "AI 문장과 제공자")만 규칙 기반 문장으로 만들고 그 사유를 보여 줍니다. 저장소와 세션이 그대로면 AI 를 다시 부르지 않고 이전 문장을 씁니다. "AI에 보내는 내용 보기"에서 보낼 텍스트(README 앞부분, 주요 코드 발췌, package.json 의 스크립트·의존성, 세션 제목·요청·요약, 사실 초안)를 먼저 볼 수 있습니다.

항목마다 근거(파일 경로 또는 세션)가 붙습니다. 파일 버튼을 누르면 **줄 번호가 있는 코드 팝업**이 열리고, 근거의 줄 범위가 있으면 강조합니다. 현재 보이는 범위에서 문자열을 찾을 수 있고 큰 파일은 500줄씩 이어서 읽습니다. 위키 작성 후 파일이 바뀌면 현재 파일이라는 안내와 함께 예전 줄 강조를 끕니다. 파일은 최대 약 200KB까지 읽으며 비밀값은 가립니다. `.env`·키 파일·숨김 설정 폴더·심볼릭 링크는 열지 않고, `.env.example`류는 변수 이름만 보여 줍니다.

**어떻게 동작하나요? → 코드 연결과 주요 처리**에는 시작 파일에서 불러오는 파일을 그래프로 그립니다. 상자는 파일을, 화살표는 코드에서 확인한 불러오기 관계를 나타냅니다. 상자나 연결 목록을 누르면 관련 코드를 볼 수 있습니다. 이는 실제 실행 순서를 추적한 결과가 아니며, 경로 별칭이나 실행 중에 정해지는 연결은 추측하지 않습니다. 기존 TypeScript 구문 분석기를 사용하고 그림은 SVG로 그려 별도 그래프 패키지를 추가하지 않았습니다.

저장소 스캔은 JavaScript·TypeScript·Python·HTML의 시작 코드와 내부 연결을 살펴보고, 주요 파일 최대 18개의 함수·클래스 선언과 코드 발췌를 위키 근거로 씁니다. AI에도 이 발췌를 비밀값을 가린 상태로 보내 README 설명과 실제 처리를 구분해 설명하게 합니다. AI가 문장을 바꿔도 파일 연결 그림과 코드의 근거 줄은 보존합니다. 새로운 코드 근거와 그림을 보려면 기존 위키에서 **업데이트**를 누르세요.

추정한 부분은 절마다 한계를 적습니다. 새 세션이 생기거나 세션·저장소가 바뀌면 "만든 뒤 바뀐 것이 있습니다"가 뜨고, **업데이트**를 누르면 다시 정리하면서 이전 판과 달라진 점(새 세션, 기능·실행 명령·API·폴더·의존성 추가/제거, 주의 항목 변화)을 기록합니다.

저장소에서 읽는 것과 읽지 않는 것:
- 읽음: 파일 목록(최대 4000개), README, package.json, requirements.txt, 소스 파일의 라우트·가져오기·함수 선언(최대 400개 파일), `.git/HEAD`
- AI에 보내는 코드: 주요 파일 최대 18개, 파일마다 최대 32줄씩 두 부분·부분당 최대 1800자. 비밀값은 가립니다. 파일 전체를 실행하거나 원본 채팅 기록을 보내지 않습니다.
- 이름만 읽음: `.env.example`·`.env.sample` 의 변수 이름 (값은 버림)
- 읽지 않음: `.env`, 키 파일(`*.pem`, `id_rsa` 등), `node_modules`·`dist`·`.git` 등 의존성·빌드 폴더, 심볼릭 링크 너머
- 저장소에 아무것도 쓰지 않고 명령(git 포함)도 실행하지 않습니다. 저장소를 읽을 수 없으면(권한 없음·폴더 없음) 세션 기록만으로 만듭니다.

저장 위치: `~/.vibe-teacher/wiki/projects/<프로젝트>/repo/` (`current.json` 지금 판의 사실 초안, `history.json` 업데이트 기록, `materials.json` AI 에 보낼 재료, `text/<수준>.json` 수준별 AI 문장).

### 보안 및 취약점 점검

레포 위키의 **보안 및 취약점 점검** 탭과 세션의 **이번 세션 이해하기** 안에서 볼 수 있습니다. 세션의 미해결·재확인 보안 및 데이터 항목을 모두 보여 주며, 설명 분량이나 개인의 이해 수준 때문에 숨기지 않습니다. 항목마다 근거, 영향, 확인 방법을 함께 보여 줍니다.

프로젝트 화면에서는 최근 세션 중 위키가 만들어진 세션 수를 표시합니다. 위키를 만들지 않은 세션은 점검 범위에 포함되지 않습니다. **접근 권한, 비밀키 노출, 잘못된 입력과 반복 요청, 외부 프로그램의 알려진 취약점, 데이터 복구**도 추가 확인 안내로 제공합니다. 이 안내는 자동 검사 결과가 아닙니다. 앱이 실제 서비스에 접속하거나 검사 명령을 실행하거나 취약점 데이터베이스를 조회하지는 않습니다. 항목이 없다는 것이 안전하다는 뜻은 아닙니다.

기존에 만든 레포 위키는 **업데이트**를 눌러 새 점검 형식을 반영하세요. 변경된 한국어 작성 지침은 새 AI 설명에 적용됩니다. 이전 문장은 다음 작성 시 새 형식으로 갱신하며, 세션 위키의 기존 사실·주의사항은 다시 만들기 전까지 유지됩니다.

### 글씨·테마·화면 설정

오른쪽 위 **톱니바퀴**를 누르면 설정 팝업이 열립니다. **본문 글씨 크기, 코드 글씨 크기, 정보 밀도, 테마, 설명 난이도**를 한곳에서 고릅니다. 화면 설정은 즉시 적용되며, Escape나 바깥쪽을 눌러 닫을 수 있습니다.

기본값은 **본문 14px, 코드 12px, 촘촘한 여백**입니다. 본문은 13·14·15·16·18px, 코드는 11·12·13·14·16px 중 고릅니다. 정보 밀도는 **촘촘하게 / 여유 있게**이며, 글씨 크기와 독립적으로 바꿀 수 있습니다. 설명 난이도를 바꿔도 글씨 크기는 그대로 유지합니다.

테마는 **기기 설정에 맞춤 / 라이트 모드 / 다크 모드** 중 고릅니다. 첫 방문에는 기기 설정을 따르고, 직접 고른 값은 이 브라우저에 저장됩니다. 새로고침하거나 다른 화면으로 이동해도 유지됩니다. 기기 설정에 맞춤을 고르면 운영체제의 색상 변경도 반영합니다.

위키 근거와 추가 설명은 필요할 때 펼쳐 읽습니다. **낯선 용어가 있나요?**에서 저장소·세션·API·빌드 같은 말을 쉬운 한국어로 확인할 수 있습니다. 세션 위에는 요약 → 보안 점검 → 작업 이해하기 → 개념 → 내 지식 순서로 이동하는 링크가 있습니다. 키보드 Tab으로 이동하면 초점이 표시되고, 탭 목록에서는 방향키·Home·End로 이동할 수 있습니다. 기기의 동작 줄이기 설정도 따릅니다.

이해 확인 문제는 한 문제씩 보여 주고, 선택한 답을 강조합니다. 생각한 이유는 원할 때 펼쳐 적을 수 있습니다. 문제와 선택지·해설을 쉬운 한국어로 다듬었으며, 정답은 제출 전까지 서버에만 있습니다. 사람이 검토하기 전인 문항은 계속 연습으로만 기록합니다.

화면 구성은 [W3C의 쉬운 문장 작성 지침](https://www.w3.org/WAI/WCAG21/Techniques/general/G153.html), [명도 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [키보드 초점](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [클릭 대상 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)를 참고했습니다.

### 내 지식 위키

로그인한 사용자 한 명에 하나이며 프로젝트를 가리지 않습니다. 내 계정의 세션(최근 40개)에서 위키 항목·먼저 확인할 것·개념 감지로 나온 개념을 모아, 개념마다 이렇게 보여 줍니다.

```
권한 검사 — 이해 미확인
로그인 기능을 만들면서 서버에서 권한을 검사하는 부분이 함께 바뀌었습니다.
이 부분을 이해했는지 확인할 만한 응답은 아직 없습니다.
근거: 회원가입 기능 구현 세션
[알고 있어요] [간단히 확인하기] [설명 보기] [추정이 잘못됐어요]
```

- **설명 문장은 AI 가 씁니다.** 코드가 모은 사실(상태, 문제 응답 수, 자기보고, 근거 세션과 그때의 요청, 대화 속 언급)만 주고 1~2문장으로 쓰게 합니다. 화면을 열면 아직 문장이 없는 항목을 자동으로 모아 쓰고(먼저 확인할 것부터, 20개씩), 그동안 그 항목에는 "AI가 설명을 쓰는 중…"이 보입니다. "모르십니다"처럼 단정하거나, 확인되지 않았는데 "이해하고 계십니다"라고 쓴 문장은 버리고 규칙 문장을 씁니다. 항목의 사실과 읽는 사람 수준이 바뀌지 않으면 다시 부르지 않습니다(`learners/<ID>/knowledge-text.json`). AI 를 쓸 수 없으면 규칙 문장에 "규칙 기반 문장" 표시와 사유가 붙습니다.

- 상태(이해 미확인 · 일부 확인 · 확인됨(문항 범위) · 판단 보류)는 문제 응답·자기보고·정정으로만 정합니다. 대화에서 그 개념을 언급한 것은 설명 문장의 맥락으로만 쓰고 이해 증거로 치지 않습니다. 붙여 넣은 글은 언급으로 보지 않습니다.
- "확인이 필요한 것 / 일부·범위 안에서 확인된 것 / 배경 개념"으로 나눕니다. 기록이 없다는 것은 모른다는 뜻이 아닙니다.
- 상단 메뉴 **내 지식**에서 전체를, 프로젝트 화면 **이 프로젝트와 관련된 내 지식**과 세션 화면 **이 세션과 관련된 내 지식**에서 그 범위만 봅니다.

저장 위치: `~/.vibe-teacher/wiki/learners/<불투명 ID>/events.jsonl` (추가만 하는 원장, 이벤트마다 어느 프로젝트·세션에서 생겼는지 남김). 예전의 프로젝트별 원장(`learners/<ID>/projects/<프로젝트>/events.jsonl`)도 함께 읽습니다.

### 이번 세션 이해하기

세션 화면은 **내가 쓴 메시지**(원본 대화) · **이번 세션 이해하기** · **만들어진 것** 세 탭입니다.

이해하기 탭은 아래를 차례로 잇고, 오른쪽에 **도움 패널**을 둡니다(좁은 화면에서는 아래 서랍).

1. **AI 설명** — 위키가 있으면 세션 요약·개념 설명과 위키 항목 설명을 AI 가 자동으로 씁니다 (아래 "AI 문장과 제공자"). 이미 써 둔 것이 있으면 다시 부르지 않고, "다시 쓰기"로 새로 쓸 수 있습니다.
2. **이번 세션 요약** — AI 보강을 했으면 요약, 다음에 해 볼 일.
3. **이번 세션에서 확인할 것** — "위키 만들기"를 누르면 사실과 위험을 규칙으로 정리하고, 이어서 AI 가 항목 설명을 씁니다 (아래).
4. **알아야 할 개념** — 규칙(+AI)으로 찾은 개념. 위키 항목에서 이미 다룬 개념은 표시됩니다.
5. **확인한 범위 · 이 세션과 관련된 내 지식**

개념 카드의 **이번 작업과의 연결**은 확인한 작업 한 가지와 그 개념을 알아두면 도움이 되는 이유를 짧게 잇습니다. 대화에서 단어만 나온 경우에는 **대화에서 언급**으로 표시하고 실제 사용 여부는 확인되지 않았다고 안내합니다. 잘린 대화와 언급 횟수를 설명으로 나열하지 않으며, 원문 발췌는 **연결된 기록 보기**를 펼쳐 확인할 수 있습니다.

설명 기준이 바뀌면 예전에 만든 세션 위키에도 갱신 안내가 나옵니다. **다시 만들기**를 누르면 새 기준으로 정리하며, 예전 판은 이력에 남습니다.

**만들어진 것** 탭은 지시 → 결과 타임라인(턴마다 바꾼 파일 포함) 아래에, 바뀐 파일을 **저장소 폴더 구조대로** 묶어 보여 줍니다(폴더마다 새 파일·수정·삭제 수). 그 아래에 명령·서버·패키지·커밋·기술 스택이 있습니다.

개념 이름, 위키 항목, 먼저 확인할 것을 누르면 도움 패널이 그 대상으로 바뀝니다.

- **설명**: 개념은 설명 깊이(짧게·기본·자세히·심화)와 예시, 이 세션에서 왜 나왔는지, 관련 위키 항목. 항목·파일은 근거와 관련 개념.
- **질문**: 지금 대상에 대해 자유롭게 묻습니다. 답은 "답 → 이번 프로젝트와의 연결 → 근거 → 일반 배경 → 확인되지 않은 것 → 이어서 물어보기" 순서입니다. 프로젝트에 관한 내용은 위키의 확인된 사실을 인용해야 하고, AI 가 없는 근거를 인용하면 그 부분은 숨기고 알립니다. AI 를 쓸 수 없으면(제공자 없음·권한 없음) 정리된 설명과 확인된 사실로 대신 답합니다. 질문은 나만 볼 수 있고(`~/.vibe-teacher/wiki/learners/…/help.jsonl`), **질문했다고 내 이해 정보가 바뀌지 않습니다.**
- **퀴즈**: 지금 대상의 개념으로 객관식·OX 문제를 풉니다. 그 개념을 도움 패널로 물어본 뒤의 응답은 "도움을 받은 응답"으로 기록되어 이해 상태 추정에 쓰이지 않습니다.

#### 이번 세션에서 확인할 것 (세션 위키)

"위키 만들기"를 누르면 그 세션 기록을 규칙으로 분석해 다음을 정리합니다(이 단계는 AI 로 보내는 데이터가 없고 명령도 다시 실행하지 않습니다). 위키가 만들어지면 곧바로 AI 가 항목마다 "이 프로젝트에서는" 설명을 쓰고, 그 설명이 규칙 문장("왜 지금")을 대신합니다. AI 를 쓸 수 없을 때만 규칙 문장이 "규칙 기반" 표시와 함께 남습니다.

- **먼저 확인할 것**: 기록에 남은 비밀값 의심, 접근 권한 검사 위치 미확인, 되돌리기 어려운 명령, 외부에 열린 개발 서버, AI API 비용 상한 미확인 같은 항목. 내 이해 정보와 관계없이 모든 사용자에게 똑같이 보입니다.
- **지금 알아 두면 좋은 것**: "로그인만 하면 누구나 이 기능을 써도 될까요?"처럼 지금 판단과 연결된 항목마다 관련 개념 설명, 먼저 이해하면 좋은 개념, 기록에서 나온 근거(발췌는 비밀값을 가림), 아직 확인되지 않은 것을 보여 줍니다. `이게 뭐예요?` `더 쉽게` `더 자세히` `예시 보기`로 설명 깊이를 바로 바꿀 수 있습니다.
- **확인한 범위와 확인하지 못한 범위**: 저장소 전체 코드와 배포 설정은 읽지 않으므로, "보이지 않음"은 이 세션 기록 안에서 찾지 못했다는 뜻으로만 씁니다. 에이전트가 "완료했습니다"라고 한 것과 실제 테스트 실행 기록도 구분합니다.

**내 이해 정보**는 본인만 볼 수 있고(관리자도 다른 사람 것은 못 봄) 프로젝트를 가리지 않고 사용자 한 명에 하나입니다(위 "내 지식 위키"). `알고 있어요` / `잘 모르겠어요`는 설명 길이에만 반영되고 이해가 확인된 것으로 치지 않습니다. `문제로 확인하기`의 객관식·OX 문제는 선택 사항이며, 건너뛰기와 "모르겠어요"는 오답이 아닙니다. 정답은 제출한 뒤에만 서버가 알려 줍니다.

> 기본 문항 은행(`server/data/questions.json`)은 코딩 에이전트가 작성한 **검토 전(candidate)** 문항이라 연습으로만 기록되고 이해 상태 추정에는 반영되지 않습니다. 문항을 직접 검토한 뒤 `"reviewStatus": "reviewed"` 로 바꾸면 반영됩니다.

| `server/data/questions.json` | 객관식(정답 1개)·OX 문항. 검사에 걸린 문항은 시작할 때 경고와 함께 제외 |

저장 위치: `~/.vibe-teacher/wiki/projects/<프로젝트>/` (세션 위키 원장과 세션별 이력).

## AI 문장과 제공자

**사실은 코드가 모으고, 사람이 읽는 문장은 AI 가 씁니다.** AI 가 쓰는 곳:

| 어디 | 언제 | 같은 입력이면 |
|---|---|---|
| 레포 위키 본문 | "레포 위키 만들기"·"업데이트"를 누를 때, 다른 수준의 사람이 처음 열 때 | 저장소·세션·수준이 그대로면 이전 문장을 씀 |
| 내 지식 설명 문장 | 내 지식 화면(프로젝트·세션 화면의 관련 부분 포함)을 열 때 자동으로, 문장이 없는 항목만 | 항목의 사실·수준이 그대로면 다시 부르지 않음 |
| 세션 요약·개념 설명, 위키 항목 설명 | 위키를 만들었을 때, 위키가 있는 세션을 열었을 때 자동으로 | 세션 기록·위키 판·수준이 그대로면 저장된 결과를 씀 |
| 도움 패널 질문의 답 | 질문할 때 | — |

모든 AI 문장에는 자연스러운 한국어 어순, 짧은 문장, 쉬운 동사, 결론 → 이유 → 다음 행동 순서의 공통 작성 지침을 적용합니다. 아래 "읽는 사람 수준"에 맞춰 쓰고, 수준을 고르기 전에는 자동으로 시작하지 않습니다.

규칙 기반 문장은 **AI 를 쓸 수 없을 때만** 씁니다: 소스 설정에서 "AI 문장 자동으로 쓰기"(`llm.autoText`)를 껐을 때, AI 권한이 없을 때(`auth.enrichFor`, 기본 관리자만), 쓸 수 있는 제공자가 없을 때, AI 호출이 실패했을 때. 이때는 화면에 그 사유가 보입니다. 이해 확인 문제와 이해 상태 판단에는 AI 를 쓰지 않습니다. 보내는 것은 다이제스트(내 메시지 요약, 파일·명령 목록, 위키 근거 발췌, README 앞부분·주요 코드 발췌 등)뿐이고 도구 출력 전문과 원본 기록은 보내지 않으며, 키처럼 보이는 값은 마스킹합니다. 화면마다 "보낼 내용 미리 보기"가 있습니다. 비용이 걱정되면 OpenRouter 무료 모델을 고르거나 `llm.autoText` 를 끄세요(끄면 새로 부르지 않고 이미 쓴 문장만 보여 주며, 세션 화면에서는 버튼을 눌러야 AI 가 씁니다).

### 읽는 사람 수준

AI 가 쓰는 모든 문장(레포 위키, 세션 요약·개념 설명, 위키 항목 설명, 내 지식 설명, 도움 패널 답)은 사용자마다 고른 **읽는 사람 수준**에 맞춰 단어와 설명 깊이를 바꿉니다. 기본은 **쉬운 일상어로(비개발자)**입니다. 이 선택은 처음에 묻던 개발 경험 수준을 문체 설정으로 표현한 것이며, 실제 지식 수준을 평가하는 설문은 아닙니다. 개념별 **알고 있어요 / 잘 모르겠어요**와 퀴즈의 이해 기록은 별도로 유지됩니다.

| 수준 | 이렇게 씁니다 | 예 |
|---|---|---|
| 쉬운 일상어로 (비개발자, 기본) | 전문 용어 없이, 무엇을 하고 왜 중요한지 먼저. 꼭 필요한 용어는 처음 한 번 괄호로 풀이 | 관리자가 가입한 사람 목록을 볼 수 있는 화면을 만들었습니다. 아무나 이 화면을 열 수 없게 막혀 있는지는 아직 확인이 필요합니다. |
| 기초부터 차근차근 (입문) | 기본 용어(파일·함수·서버·패키지)는 그대로, 어려운 용어는 처음 나올 때 한 줄 설명 | 관리자용 회원 목록 화면과, 서버가 목록을 보내 주는 API(프로그램끼리 정보를 주고받는 주소)를 만들었습니다. … |
| 개발 용어에 익숙해요 (주니어) | 흔한 용어는 설명 없이, 이 프로젝트 특유의 것만 짚음 | 회원 목록을 돌려주는 `GET /admin/users` 와 관리자 페이지를 추가했습니다. 라우트에 관리자 권한 검사가 걸려 있는지 확인이 필요합니다. |
| 핵심만 자세하게 (숙련) | 용어·기초 설명 생략, 구조·설계·위험만 짧게 | `GET /admin/users` 추가. 인가 미들웨어 적용 여부 미확인. |

- **처음 한 번 묻습니다**: 로그인 후 아직 고르지 않았으면 화면 위에 "어떤 설명이 편한가요?"가 뜨고, 고르기 전에는 AI 가 자동으로 문장을 쓰기 시작하지 않습니다(레포 위키는 만들기 버튼 위에서 고를 수 있음).
- **언제든 바꾸기**: 오른쪽 위 **톱니바퀴 → 설명 난이도**, 또는 각 문서 위의 "읽는 사람: … · 바꾸기"(같은 설정 팝업을 엽니다). 바꾸면 그 수준의 문장을 새로 쓰고, 이미 쓴 수준의 문장은 저장돼 있어 되돌아가도 다시 부르지 않습니다.
- 이 선택은 **문장의 쉬운 정도에만** 쓰입니다. 내 이해 상태 추정, 위험 알림(먼저 확인할 것), 사실·근거에는 영향을 주지 않습니다. AI 를 쓸 수 없을 때 보이는 규칙 기반 문장은 수준에 따라 바뀌지 않습니다.
- 저장 위치: `~/.vibe-teacher/wiki/learners/<불투명 ID>/prefs.json`

| 제공자 | 조건 | 비고 |
|---|---|---|
| `claude-cli` | 로그인된 Claude Code. `claude` 를 설정 `claudeCliPath` → PATH → `CLAUDE_CODE_EXECPATH` → `~/.local/bin`·`~/.claude/local` → VS Code·Cursor 의 Claude Code 확장 폴더(가장 새 버전) 순으로 찾음 | `claude -p --output-format json --json-schema … --no-session-persistence --tools "" --restricted` 로 실행. 별도 API 키 불필요 |
| `anthropic-sdk` | `ANTHROPIC_API_KEY` | 기본 모델 `claude-opus-5-5` (입력 $4 / 출력 $20 per 1M 토큰), `effort` 기본 `medium`. 안전 분류기가 거절하면 서버가 권장 모델로 다시 실행합니다(`fallbacks: "default"`) |
| `openrouter` | `OPENROUTER_API_KEY` | 기본 모델 `openrouter/free`(무료 모델 라우터). 소스 설정에서 OpenRouter 모델 목록 중 고를 수 있음 |
| `openai` | `OPENAI_API_KEY` | 기본 모델 `gpt-5-mini`. 키가 있으면 OpenAI 모델 목록 중 고를 수 있음 |
| `auto` (기본, GPT 우선) | OpenAI 키 → Anthropic API 키 → Claude Code 로그인 → OpenRouter 키 순 | 모두 없으면 규칙 기반 결과만 표시 |

**기본 글 작성 모델**: 자동 모드에서 `OPENAI_API_KEY`가 있으면 OpenAI의 `gpt-5-mini`를 먼저 사용합니다. 이미 제공자를 직접 골랐다면 그 선택과 환경변수 강제 설정이 우선합니다. OpenAI 키가 없으면 기존 제공자를 계속 쓸 수 있습니다. 모델만으로 한국어 품질을 보장하지 않으므로 공통 작성 지침과 기본 문구·문항도 함께 관리합니다. 모델은 소스 설정에서 바꿀 수 있습니다.

**AI 키 넣는 곳**: 저장소 루트에서

```bash
cp .env.example .env && chmod 600 .env   # 그다음 .env 의 OPENAI_API_KEY= 뒤에 키를 붙여넣기
npm start                                # 또는 npm run dev — 시작 로그에 ".env 를 읽었습니다" 가 보이면 됨
```

`.env` 는 `.gitignore` 에 들어 있어 커밋되지 않습니다. 셸에서 `export OPENAI_API_KEY=…` 로 넣어도 되고, 그쪽이 `.env` 보다 우선합니다. 키를 바꾼 뒤에는 서버를 다시 시작하세요.

**AI 제공자 고르기** (관리자): 소스 설정 페이지의 "설명을 작성할 AI", 또는 AI 버튼 아래의 "지금 쓰는 AI · 바꾸기"에서 **Claude Code 로그인 / Anthropic API 키 / OpenRouter / OpenAI / 자동 / 사용 안 함** 중 하나를 고릅니다. 선택지마다 지금 실제로 쓸 수 있는지(CLI 버전, 키 유무)가 함께 보입니다. 환경변수 `VIBE_TEACHER_LLM_PROVIDER` 가 있으면 화면의 선택보다 우선합니다.

OpenRouter 를 고르면 모델 선택이 나타납니다. 목록은 OpenRouter 의 공개 모델 목록(`https://openrouter.ai/api/v1/models`)에서 가져오며(1시간 캐시, "목록 새로고침"으로 다시 받기), 기본으로 **무료 모델만** 보여 줍니다. 모델마다 가격, 컨텍스트 크기, JSON 스키마 강제 지원 여부가 표시됩니다. 지원하지 않는 모델은 JSON 모드나 프롬프트 지시로 대신하므로 형식이 틀려 실패할 수 있습니다. 무료 모델은 공급자가 입력을 기록하거나 학습에 쓸 수 있고 요청 한도가 낮으니, 민감한 기록에는 유료 모델이나 Claude 를 쓰세요. 무료 모델이 "data policy" 오류를 내면 OpenRouter 계정 Settings › Privacy 에서 무료 모델 사용을 허용해야 합니다. OpenAI 를 고르면 키가 있을 때 계정의 모델 목록에서 고를 수 있습니다.

Claude Code 세션 안에서 이 앱을 띄워도 중첩 실행이 막히지 않도록, 자식 프로세스에서는 `CLAUDE_CONFIG_DIR` 를 제외한 `CLAUDE*` 환경변수를 제거합니다. "Claude Code 로그인"을 고르면 `ANTHROPIC_API_KEY` 가 설정되어 있어도 `claude` 에는 넘기지 않으므로, 키가 아니라 로그인(구독)으로 실행됩니다.

### 세션 위키 AI 설명

위키가 만들어지면 세션 요약과 함께 위키 항목 설명을 AI 가 자동으로 씁니다. AI 를 쓸 수 있는 사람은 설정 `auth.enrichFor` 로 정합니다(기본 관리자만, 나머지는 규칙 문장과 AI 없는 대체 답).

- **보내는 내용**: 위키 근거 발췌(비밀값 가림), 내 메시지 요약, 파일·명령 목록, 위키 항목과 개념 목록. "보낼 내용 미리 보기"에서 실제로 보낼 텍스트를 먼저 확인할 수 있습니다. 원본 기록 파일과 도구 출력 전문은 보내지 않습니다.
- **AI 가 하는 일**: 항목마다 이 프로젝트에 맞춘 설명, 기록에서 직접 확인되는 새 사실 후보, 놓친 항목 후보, 카탈로그에 없는 개념 제안.
- **코드가 검사하는 것**: 인용한 근거·주장·항목·개념 ID 가 실제로 있어야 하고, 하나라도 지어낸 ID 가 있으면 그 제안 전체를 버립니다. 프로젝트에 관한 문장은 근거 주장을 하나 이상 인용해야 합니다. 걸러 낸 제안은 이유와 함께 "검사에서 걸러 낸 AI 제안"에 보입니다.
- **AI 가 바꾸지 못하는 것**: 위험 알림(먼저 확인할 것)과 그 상태·영향. AI 가 쓴 설명·사실·항목에는 "AI 작성", "AI 후보", "AI 제안 · 검토 전" 표시가 붙고, AI 가 제안한 항목은 규칙 기반 항목 뒤에 놓입니다.
- **저장**: `~/.vibe-teacher/wiki/projects/<프로젝트>/ai/<snapshot>.<읽는 사람 수준>.json` 에 규칙 기반 원장과 따로 저장됩니다. 세션 요약·개념 설명도 수준별로 캐시합니다. 같은 snapshot 에서는 저장된 결과를 다시 쓰고, "다시 쓰기"를 누를 때만 새로 호출합니다. 세션 기록이 바뀌면 위키를 다시 만들면 됩니다(새 판에 대해 자동으로 다시 씁니다).

claude CLI 로 실행할 때 `llm.maxBudgetUsd`(기본 0.5달러)가 요청 상한입니다. 위키 보강은 세션 분석보다 입력이 커서(큰 세션은 약 4~5만 자) 모델에 따라 상한을 넘을 수 있으니, "예산 초과" 오류가 나면 소스 설정에서 올려 주세요.

## 다중 계정 운영 (서버 전체 조회)

다른 계정의 홈은 보통 `drwxr-x---` 이고 Claude 세션 파일은 `0600` 이라 일반 계정으로는 읽을 수 없습니다. 앱을 돌리는 계정(서비스 계정, 예: `user99`)에 **읽기 전용 ACL** 을 주면 root 로 실행하지 않고도 전체를 읽을 수 있습니다. `/home` 이 ext4/xfs 라면 ACL 은 바로 쓸 수 있습니다.

```bash
# 1) 도구 설치 (Ubuntu)
sudo apt update && sudo apt install -y acl

# 2) 서비스 계정에 읽기 ACL 부여 — 홈 진입(rx) + 기록 디렉터리 재귀(rX) + 새 폴더 상속
#    (다른 계정으로 실행하면 user99 홈을 못 읽으므로 sudo bash + 절대 경로로)
sudo bash /home/user99/vibe-teacher/scripts/grant-read-acl.sh user99                 # /home/* 전체
sudo bash /home/user99/vibe-teacher/scripts/grant-read-acl.sh user99 user01 user02   # 특정 사용자만

# 3) 확인 (getfacl 도 남의 홈이므로 sudo)
sudo getfacl /home/user01/.claude | head               # user:user99:r-x 가 보이면 됨
sudo -u user99 ls /home/user01/.claude/projects        # 목록이 나오면 성공

# 4) 주기적 재적용 — 시스템 경로에 복사해 두고 root crontab(sudo crontab -e)에 등록
sudo install -m 755 /home/user99/vibe-teacher/scripts/grant-read-acl.sh /usr/local/sbin/vibe-acl
*/10 * * * * /usr/local/sbin/vibe-acl user99 >/dev/null 2>&1

# 되돌리기
sudo setfacl -R -x u:user99 /home/user01               # 해당 사용자 홈에서 user99 항목만 제거
sudo setfacl -R -b /home/user01                        # 그 홈의 ACL 전부 제거
```

스크립트가 하는 일을 손으로 하면 다음과 같습니다.

```bash
sudo setfacl -m u:user99:rx /home/user01
sudo setfacl -R -m u:user99:rX /home/user01/.claude /home/user01/.claude.json /home/user01/.codex /home/user01/.copilot
sudo setfacl -R -d -m u:user99:rX /home/user01/.claude /home/user01/.codex /home/user01/.copilot   # 새로 생기는 폴더 상속
```

4번(주기적 재적용)이 필요한 이유: default ACL 은 새 파일에도 상속되지만, Claude Code 가 세션 파일을 `0600` 으로 만들면 ACL 마스크가 0 이 되어 **상속된 항목의 실효 권한이 없어집니다**. 재귀 `setfacl -R -m` 을 다시 돌리면 마스크가 열립니다. 10분 주기면 충분합니다.

그 계정으로 앱을 실행하고 소스 설정에서 스캔 범위를 `/home 전체` 로 바꾸면 계정 › 프로젝트 › 세션 계층으로 볼 수 있습니다. 권한이 없는 계정은 "권한 없음"으로 표시되고 나머지는 정상 동작합니다.

## 로그인 (사용자별 접근 제한)

서비스 계정이 전체를 읽되, 각 사용자는 **자기 계정 기록만** 보게 하려면 홈 디렉터리 토큰 로그인을 켭니다. 원리: 사용자의 홈 안에 `~/.vibe-teacher/login-token` 파일을 만들면 그 파일을 읽을 수 있는 사람은 그 계정(과 서비스 계정)뿐이므로, 그 문자열을 아는 것이 본인 증명이 됩니다. 비밀번호도, 개인 키 업로드도 필요 없습니다.

```json
"auth": { "mode": "home-token", "admins": ["user99"], "sessionTtlHours": 168, "enrichFor": "admins" }
```

- `mode`: `none`(기본, 로그인 없음) 또는 `home-token`
- `admins`: 모든 계정을 볼 수 있는 사용자. 앱을 실행한 OS 계정은 항상 관리자입니다.
- `enrichFor`: AI 분석을 누구에게 허용할지 (`admins` 또는 `everyone`). 서비스 계정의 Claude 계정으로 비용이 나가므로 기본은 관리자만입니다.

각 사용자는 서버에 SSH 로 들어가 한 번만 다음을 실행하고, 출력된 문자열을 로그인 화면에 붙여넣습니다 (로그인 화면에도 같은 안내가 나옵니다. `user99` 자리는 서비스 계정 이름).

```bash
( umask 077; mkdir -p ~/.vibe-teacher; head -c 32 /dev/urandom | base64 | tr -d '/+=\n' > ~/.vibe-teacher/login-token; setfacl -m u:user99:rx ~ ~/.vibe-teacher; setfacl -m u:user99:r ~/.vibe-teacher/login-token; cat ~/.vibe-teacher/login-token )
```

토큰 파일을 지우거나 다시 만들면 그 사용자의 기존 로그인 세션은 모두 무효화됩니다. 로그인 5회 실패 시 1분간 잠깁니다. 로그인 모드에서는 비-loopback 바인딩에 `VIBE_TEACHER_TOKEN` 이 필수는 아니지만, 토큰이 네트워크를 타므로 HTTPS 앞단(nginx 등)이나 SSH 터널을 권장합니다. `VIBE_TEACHER_TOKEN` 을 설정하면 그 값은 관리자용 API 토큰(`Authorization: Bearer`)으로 계속 쓸 수 있습니다.

### 원격 접근

기본은 `127.0.0.1` 에만 바인딩합니다. 다른 PC 에서 보려면 SSH 터널을 권장합니다.

```bash
ssh -L 8787:127.0.0.1:8787 <server>
```

부득이하게 외부 주소로 열어야 하면 토큰이 필수입니다 (없으면 부팅을 거부합니다).

```bash
VIBE_TEACHER_HOST=0.0.0.0 VIBE_TEACHER_TOKEN='긴-무작위-문자열' npm start
```

UI 에서 처음 한 번 토큰을 입력하면 브라우저에 저장됩니다.
